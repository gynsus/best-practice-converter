# Конвертер прайс-листов (Python)

Замена XLSM/VBA-конвертера: преобразует прайс-листы поставщиков (xlsx/xlsm/xls/xml)
в CSV единого формата (21 колонка, `;`, UTF-8 с BOM) для загрузки во внешнюю
систему. Реализован по ТЗ «Разработка конвертера файлов прайс-листов» и
спецификации маппингов ТЗ V2; план и принятые решения — `../python_converter_plan.md`.

## Архитектура

- `main.py` — основной скрипт (ТЗ 4.1): читает `settings.yaml`, находит
  прайс-листы во входном каталоге (точное имя или маска), решает, что запускать,
  архивирует исходники в подкаталог `ГГГГ.ММ.ДД`, ведёт сквозную нумерацию
  строк «без зазоров», пишет отчёт прогона и `done.txt`;
- `workers/<имя>.py` — воркер на каждый прайс-лист; общий контракт
  `process(src, out, start_number, ctx) -> WorkerResult`;
- `common/` — библиотека: чтение исходников (маппинг по именам колонок с
  валидацией), очистка строк (ТЗ 4.2.1), числа (все форматы, включая
  экспоненту; вывод без научной нотации), справочники (валюты, качество,
  некондиция), сборка CSV;
- `tools/profile_csv.py` — профайлер результатов для самопроверки;
- `tests/` — unit- и регресс-тесты на реальных исходниках из `fixtures/`.

## Установка (ВМК)

```bash
python3 -m venv .venv   # Python 3.9+
.venv/bin/pip install -r requirements.txt         # openpyxl, PyYAML
```

Запуск планировщиком (cron / Планировщик задач Windows), «пассивный» режим —
никакой самодеятельности, только внешний вызов:

```bash
.venv/bin/python main.py --settings settings.yaml
```

Коды возврата: `0` — успех; `1` — часть прайсов с ошибкой (подробности в
отчёте); `2` — фатальная ошибка настроек/каталогов.

## Настройки

`settings.yaml`: три каталога (вход/выход/архив) и таблица прайс-листов.
Порядок записей = порядок обработки и нумерации. Ключевые сценарии:

- **поставщик сломал формат** → `enabled: false` у его записи, остальные
  работают; воркер при смене структуры падает с диагнозом
  «не найдена колонка …» — данные со сдвигом не выгружаются никогда;
- **у поставщика несколько прайсов** (почтовый/B2B) → несколько записей с
  разными масками (`price_mail*`, `price_b2b*`) и своими воркерами.

## Отладка одного прайса

Каждый воркер запускается автономно:

```bash
python3 -m workers.getsy /path/Getsy.xlsx -o /tmp/Getsy.csv --start 1
python3 tools/profile_csv.py /tmp   # сводка по колонкам результата
```

## Как добавить новый прайс-лист

1. Скопировать ближайший по духу воркер в `workers/<новый>.py`;
2. заполнить маппинг по листу ТЗ V2: имена колонок исходника, лист, строка
   заголовка, константы (поставщик, валюта по умолчанию, качество);
3. добавить запись в `settings.yaml`;
4. положить образец исходника в `fixtures/` и добавить тест в
   `tests/test_workers.py` (число строк + ключевые значения);
5. `python3 -m pytest tests/ -q`.

## Ключевые правила формата (решения от 17.09.2026)

- разделитель `;`, UTF-8 **с BOM**, 21 колонка, заголовок фиксированный;
- габариты — **сантиметры**; вес — кг; объём — м³, при отсутствии у поставщика
  **вычисляется из габаритов** (ТЗ 3.2.12);
- пустое числовое значение = **пусто** (не 0); реальный 0 исходника сохраняется;
- «Состояние» — всегда заполнено, по умолчанию **«Стандарт»** (закрытый список
  ТЗ 3.2.8 + константы ТЗ V2 «Некондиция»/«Распродажа»);
- НДС — пусто, если поставщик не дал;
- валюта обязательна (словарь ТЗ табл. 1: RUR/руб./₽→RUB, $→USD, €→EUR);
- количество и гарантия — прямое копирование без интерпретации (ТЗ 3.2.14/17);
- десятичный разделитель в числах — запятая, научная нотация запрещена;
- очистка строк: `;`→`,`, `"`→`''`, непечатаемые→пробел, схлопывание пробелов.

## Тесты

```bash
python3 -m pytest tests/ -q
```

Регресс-набор закрепляет исторические баги старого конвертера (сдвиги колонок,
потеря E-значений, суффиксы качества, сквозная нумерация и т.д.).

### Задокументированные отличия от v112 (сверх согласованных решений)

Проверено построчным сравнением с выгрузкой v112 от 31.08 (все расхождения
классифицированы; полный разбор — `../python_vs_v112_report.html`).

По спецификации ТЗ V2 (v112 от неё отклонялся):
- **Komus: цена из «8-й колонки ОПЛ»** (v112 брал «Базовую цену» — отличие в
  44 тыс. строк); Состояние из «Статуса товара» (Регулярный -> Стандарт);
- **3LOGIC и Merlion: цена в рублях** («Руб.» / «Цена(руб)», валюта RUB;
  v112 выгружал долларовые колонки); гарантия 3LOGIC дописывается « мес»;
- **A1TIS: количество = ВЫБОР(первое числовое)** — «Заказ» в «В наличии»
  пропускается, берётся транзит (v112 суммировал наличие с транзитами);
- **iDistribute: количество из «В наличии»** (v112 брал «Доступно»);
- **NetLab: Код = offer.uid** (v112 — атрибут id), «Название» = текст из
  [скобок] RussianName, «Наименование» = offer.name без префикса;
- **Resurs Struct: Артикул = «Артикул производителя»** (v112 — «Артикул»
  со служебным суффиксом);
- **VTT: Код = «Артикул», Артикул = «Ориг. номер»** с fallback на
  «Каталожный номер»/код (v112 клал код поставщика в артикул, код не заполнял).

Исправленные дефекты v112:
- **Artron: +2 строки** — v112 начинал чтение со строки 17 и терял два первых
  товара; **Citilink/OCS: E-значения объёма/веса живы** (v112 обнулял ~3 тыс.);
- **Marvel: детальные качества по ТЗ табл. 3** (вскрытая -> Дефект упаковки,
  с теста -> Демо…; v112 всё звал «Уценка»); **MICS: полный путь группы**
  (v112 терял нижний уровень); **нечисловые коды** Citilink/OCS сохраняются
  (v112 писал 0); **VVP: гарантия из колонки исходника** (v112 — хардкод).

Прочее:
- **«-->» в наименованиях** сохраняется как есть (v112 портил в «- -> »);
- **ProWay SUPER SALE** помечается «Распродажа» (в спеке V2 поле пусто);
- Resurs-некондиция и ABSOLUT LOT-категории идут детальными текстами
  исходников (extra_allowed); Getsy/OCS: редкие строки без групп наследуют
  группу предыдущей строки;
- артефакты вида «27,081000000001» в единичных ценах — значения исходников
  (v112 выгружал так же).
